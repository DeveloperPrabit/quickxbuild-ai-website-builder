---

## SCENE 2 — BODY (0:35–2:20)

### Beat A — Prompt → build (0:35–1:10)

**On screen:** Chat panel. Type a short prompt (or show one already typed).

**Example prompt to show:**

> Build a modern website for Insane Barber in Chandragiri — home, about, contact, and online booking.

**Say:**

> I send one prompt. Muse Spark is the coding agent behind QuickXBuild — via Meta’s Model API. It plans the site, then uses tools to create and edit real files: pages, components, styles — not a fake mockup.

**Visual:** Agent runtime logs / tool calls scrolling (Editing App.tsx, Contact, Booking…).

### Beat B — Live preview (1:10–1:45)

**On screen:** Preview tab — Insane Barber hero, Book a Chair, navigation.

**Say:**

> Here’s the live preview inside the IDE. Same URL works in a new tab — and the Preview tab embeds it safely so judges can see the product, not a blank iframe.
>
> This isn’t a slide deck. It’s a real Vite app running in a sandbox, generated by Muse.

**Visual:** Click Book a Chair / scroll About / Contact quickly.

### Beat C — Iterate by chat (1:45–2:20)

**On screen:** Chat: “Make the About page clearer and fix the Contact layout.”

**Say:**

> Need a change? I don’t open the code editor first — I ask Muse again. It reads the files, patches the layout, and the preview updates.
>
> That’s the product loop: describe → Muse builds → preview → refine. Built for people who know their business, not TypeScript.

## Recording tips

1. Hard-refresh Preview before recording so the site is visible.
2. Keep agent logs visible 3–5 seconds (proves Muse tool use).
3. No secrets on screen (.env, API keys).
4. Export 1080p; upload YouTube/Loom Unlisted or Public; paste URL in the form.
